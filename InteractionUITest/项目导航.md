# InteractionUITest 项目导航

> 面向不熟悉 Qt 的读者。基于对全部源码（2200 行 Python）的通读整理。
> 项目现状：**Python + PyQt5**，没有 C++ Qt，也没有 `.ui` / `.qrc` / `.pro` 文件——所有界面都是手写代码搭建的。

---

## 0. 一句话概括

这是从原项目 `Huishou_2` 抽出来的**界面壳 + 语音操控**：保留 4 个页面的显示与跳转，剥离了登录、数据库、设备连接、模型加载。
在界面壳之上加了一层 **AI 语音操控**：说一句话 → AI 判断该点哪个按钮 → 自动点一次（不做 agent loop）。

## 4. 必须先懂的 6 个 Qt 概念

| Qt 概念 | 一句话解释 | 本项目在哪 |
|---|---|---|
| `QApplication` + `exec_()` | 唯一的事件循环，所有点击/重绘在其中排队执行 | `main.py` |
| `QWidget` | 一切可视元素的基类 | 所有类 |
| **Layout（布局）** | 不用坐标摆控件，交给 `QVBoxLayout`/`QHBoxLayout` 自动排列 | 各 `_build_ui()`；`FlowLayout` 是自定义的自动换行布局 |
| **Signal / Slot（信号槽）** | Qt 的事件回调：`emit` 信号，`.connect()` 绑定处理函数；**跨线程时自动排队到接收者所在线程** | 全项目最常见的写法 |
| `QStackedWidget` | "多页卡片盒"，同一时刻只显示一页 | `window.py` 的 `TestWindow` |
| **QSS 样式表** | 类似 CSS 的字符串；`#名字` 匹配 `objectName`；改 property 后要 `unpolish/polish` 才刷新 | `theme.py:APP_STYLE`、各控件局部覆写 |

**信号槽实例（理解全项目的钥匙）**

```python
# 定义
active_requested = pyqtSignal()
# 发出
active.clicked.connect(self.active_requested.emit)
# 接收
self.home.active_requested.connect(lambda: self.show_page("active"))
```

层层转发：卡片 `clicked` → 页面的 `active_requested` → 窗口的 `show_page("active")`。
**每个页面只对外发信号、不直接操作窗口**，所以页面可以搬走复用，AI 模块也只需要发信号。

## 5. 三种"画界面"的方式（本项目都用了）

1. **布局 + 控件**（骨架）：`QPushButton`、`QLabel`、`QFrame` + Layout。
2. **QSS 样式**（皮肤）：圆角、渐变、悬停。`theme.py:page_background()` 会把整段 `APP_STYLE` 设到每个页面根上，页面里再局部覆盖——**后设置的局部样式盖住全局**。
3. **`paintEvent` + `QPainter` 手绘**（装饰）：渐变背景、波浪、点阵、折线图、`HandIcon` 的手掌。**想换背景/图标改这里，不是改图片。**

## 6. 手势选择页的内部逻辑（`gesture_cards.py`）

```
GestureStageSelector
├── 顶部 Tab 行：按 GESTURE_GROUPS 的 key 生成"布氏一期…五期 + 自由选择"（互斥选中）
├── 提示条："请选择适合当前阶段的训练手势"
└── QScrollArea → content(QWidget) + FlowLayout
        └── 每个手势一个 GestureImageCard(360×360)：图片 + 名称 + 右上角 ✓
```

- **数据来源**：`gesture_config.py` 的 `GESTURE_GROUPS`（分期 → 手势名）与 `SELECTABLE_GESTURES`（手势名 → 图片/标号）。
- **选中状态**：`_selected` 是集合，**跨 Tab 保留**。`selected()` 按配置顺序返回全部已选。
- **点击流程**：`mouseReleaseEvent` 自己翻转勾选 → 发 `clicked` → `_toggle_selection` 写进集合。
- **切 Tab 会整块重建** `content`，卡片对象是临时的，别在外面长期持有引用。

### ⚠️ 自动化专用的坑（已封装成公开方法）

1. **卡片状态存在两处**：卡片自己记 `_checked`，selector 另有 `_selected`。
   只调 `card.setChecked(True)` 会出现"界面打勾了但 `selected()` 还是空"。
   → 用新增的 `selector.set_gesture_selected(name, True)`，它内部会 `setChecked` + `emit clicked`，等价于用户点了一下。
2. **`_visible_cards` 只含当前 Tab 的卡片**，查别的分组会 `KeyError`。
   → `set_gesture_selected()` 会按需先切分组再查表。
3. **同一个手势属于多个分期分组**（20 个手势里有 14 个是多分组的，比如「五指伸展」在一期/二期/三期/自由选择里都有）。
   所以选分组时**必须先判断当前分组里有没有这个手势**，有就原地勾选；直接取「第一个包含它的分组」会把用户从当前分期硬拽走。
   这个坑曾经真实出现过：在布氏三期说「五指伸展」，界面会跳到布氏一期。
4. **不要用坐标模拟鼠标**（`QTest.mouseClick`）：本项目的卡片是 `QFrame` 子类，没有 `.click()`，坐标又随布局变化。统一走动作注册表。

## 7. AI 语音操控（`app/ai/`）

### 7.1 一句话说清它怎么工作

```
 麦克风
   │
   ▼
VoiceWorker (QThread)   Qwen3-ASR
   │  pyqtSignal(str)  ── 跨线程安全 ──┐
   ▼                                  │
IntentRouter（主线程）                 │
   ├─(1) 正则快速通道：fast=True 的动作别名命中 → 0.14ms 出结果
   ├─(2) 未命中 → LlmWorker (QThread) → llama-server 工具调用（服务由 server.py 自动拉起）
   │        tools=[{click_button: {action_id: enum[...]}}]
   ├─(3) 回表校验：id 必须在"当前页动作表"里，否则丢弃
   └─(4) 主线程执行 action["run"]()
```

**为什么是工具调用**：实测（见 `AI操控方案.md`）工具调用准确率最高（100% / 91.7%），
"自由文本 + 正则提取"只有 58%~75% 且慢 3 倍；纯正则快但会把"环状抓握"错配成"抓握"。

### 7.2 怎么用

**不需要手动起 llama-server**，直接启动界面就行：

```bash
cd InteractionUITest && ~/miniconda3/envs/ai/bin/python main.py
```

程序启动时会先探测 `http://127.0.0.1:8081/health`，然后按情况处理：

| 情况 | 行为 |
|---|---|
| 已经有服务在跑（比如你自己起的） | 直接用它，**不重复起第二个**（两个抢同一端口，第二个必然绑定失败）；关窗口时**也不会杀它** |
| 没有服务 | 自动拉起，参数与手动敲的完全一致；日志写到 `~/.cache/ui-test/llama-server.log` |
| 关窗口 | 只结束“自己拉起来的”那个进程，不留孤儿 |
| 模型还在加载时说话 | 状态条提示“AI 服务还在启动，请稍等几秒再试” |

界面里的操作：点左下角 **🎤 语音操控** → 说话 → 再点一次结束 → 自动识别并点击。

状态条会依次显示 `录音中…` → `正在识别…` → `听到：xxx` → `正在判断该点哪里…` → `已点击「xxx」（AI）`；
没听懂时显示「没听懂，这个页面上没有对应的操作」，此时**不点任何东西**。

> 排查用：自动拉起的命令就是下面这条，可以手动跑一遍看报错。
> ```bash
> ~/llama.cpp/build/bin/llama-server -m ~/模型/Qwen3.5-9B-DeepSeek-V4-Flash-Q4_K_M.gguf \
>     --host 127.0.0.1 --port 8081 -ngl 99 -c 8192 --jinja
> ```

### 7.4 加一个新页面的 AI 操作（只改一个文件）

在 `app/ai/actions.py` 里加一个函数，返回动作列表，并注册进 `build_registry()`：

```python
def _my_page_actions(window):
    page = window.my_page
    return [
        _action(
            "start_training", "开始训练",      # id 用英文，label 是给模型看的中文
            "开始一次康复训练，会加载模型",     # desc 越具体，模型判断越准
            lambda: page.start_requested.emit(),  # 怎么点：直接调信号/方法
            aliases=["开始", "开始训练"],       # 可选：给正则快速通道用
            fast=True,                          # 可选：只给确定性极高的命令开
        ),
    ]
```

**加完就完事**——工具调用的 enum、正则、回表校验都自动从注册表派生，不用碰 `router.py` 或 `llm.py`。

### 7.5 两条设计约定

- **`fast=True` 要克制**。只给"返回/下一步"这类命令开。给手势名开快速通道会踩子串重叠的坑（"环状抓握"含"抓握"）。默认 `fast=False` 走模型更安全。
- **动作表描述"这个页面能做什么"，不是"此刻屏幕上画了什么"**。手势页的动作覆盖全部 20 个手势，即使它们不在当前 Tab。
  执行时 `set_gesture_selected()` 的策略是：**当前分组里有这个手势就原地勾选，没有才切分组**——绝不要写成"一律切到第一个包含它的分组"，那会把用户从当前分期拽走（见第 6 章第 3 条）。

### 7.7 ⚠️ QThread 生命周期（踩过一次崩溃，改代码前必读）

**症状**：说完话、界面进入"正在判断该点哪里…"，1~2 秒后进程被 `SIGABRT` 杀掉（systemd 报 `Signal 6`），堆栈长这样：

```
QMessageLogger::fatal
QThread::~QThread          <-- Qt 发现"线程还在跑就被销毁了"
sipQThreadD0Ev
forgetObject -> sipWrapper_dealloc -> _Py_Dealloc
_PyDict_SetItem_Take2 -> PyObject_GenericSetAttr   <-- 某处 self.xxx = None
_PyEval_EvalFrameDefault -> PyQtSlot::call          <-- 发生在一个槽函数里
```

**原因**：`LlmWorker` 是 `QThread`，没有 C++ 父对象，**它的生命周期完全由 Python 引用计数决定**。
而 QThread 内部的收尾顺序是：

```
run() 返回 -> sip 释放包装引用 -> d->running = false -> emit finished
                                ^^^ 这个窗口里，线程还没被标记为结束
```

如果在 `finished_with_id` / `failed` 槽里写 `self._worker = None`，最后一个引用就可能落在这个窗口里被释放，
于是 `QThread::~QThread()` 检测到 `running == true` -> `qFatal` -> 进程被 abort。

**铁律**：

1. **worker 的引用只能在线程发出 `finished` 之后释放**。`IntentRouter` 用 `self._workers` 集合持有强引用，只在 `_release_worker()` 里 `discard`（此时 Qt 已把线程标记为结束，安全）。
2. **`finished_with_id` / `failed` 的槽里绝对不许动引用**，只做业务判断；判断"有没有在忙"看 `self._busy`，**不要靠 `isRunning()`**。
3. 别 `del`、别赋 `None`、别用局部变量"临时"持有正在运行的 QThread。
4. 关窗口要先把线程等回来：`TestWindow.closeEvent` -> `AiController.shutdown()` -> `IntentRouter.shutdown()`；退出瞬间析构运行中的线程是同一个 abort。
5. 语音线程同理，见 `controller._voice_workers`（每次录音前顺手清理已结束的旧线程）。

> 这个 bug 只在"工作线程刚好在收尾、主线程刚好去处理信号"的窄窗口里触发，**平时跑一百次可能都不复现**。
> 修复后已用 12 轮真实模型压测 + 完整语音链路（录音->ASR->路由->点击）验证通过；不要因为"我这儿没事"就改回原来的写法。

## 10. 几个小提醒

- `pages/home_page.py` 放在 `pages/` 下却没有页面类，只有可复用控件；`rehab_mode_page.py` 反过来装了**两个**页面类。最容易找错文件的地方。
- 没有任何 DPI/分辨率适配代码，字号写死 `px`，小屏可能挤。
- 语音模型首次加载约 3~5 秒（之后常驻），所以**第一句话会慢一点**，状态条会显示"正在加载语音模型…"。
- 单次 AI 判断约 1.2~2.3 秒，主要花在模型的思考 token 上（试过四种关思考的参数都无效，详见 `AI操控方案.md`）。
- 悬浮条是窗口的直接子控件，`QStackedLayout` 切页时会把当前页 `raise()` 到它上面，所以 `controller` 里监听了 `page_changed` 重新置顶——**改窗口结构时别把这个连接删了**。
- **AI 模块里的 QThread 有严格的生命周期要求**：worker 的引用只能在线程发出 `finished` 之后释放，否则会随机 `SIGABRT`（退出码 134）。详见 7.7 节。
- 崩溃排查入口：`coredumpctl list` / `coredumpctl info <PID>`。Qt 的 `QThread: Destroyed while thread is still running` 是 abort 而非 Python 异常，`try/except` 抓不到，只能看堆栈。
- 不需要手动起 `llama-server`：程序会探测 `http://127.0.0.1:8081/health`，没有才自动拉起，关窗口只收自己起的那个（见 7.2）。
- **别用 `pkill -f llama-server`**：`-f` 匹配完整命令行，会把执行这条命令的 shell 自己也匹配上，导致命令无声中断。用 `pkill -x llama-server`。
